# Scene Mock：现有素材能撑起什么样的像素房间

> 目标：不写代码、不改素材，只用仓库里已有的三张图集（`tiles.png` / `furniture.png` / `carpets.png`）+ 角色帧，手工合成一间「客厅 + 厨房一角」的像素 mock，回答一个问题：**现有素材到底能不能撑起像样的像素风，还是必须换素材库。**
>
> 结论先行：**勉强（Borderline）**——靠手工分帧、分层拼墙、脚本补阴影/成光，能做出「单间演示房」级别的画面；但素材本身缺墙体系统、门窗状态、灯光层、多格地毯、冰箱/淋浴等生活模拟刚需，撑不起多房间公寓与交互状态。详见 §5–§7。

## 1. mock 构图说明

### 1.1 尺寸与图层顺序

逻辑网格 16px，画布 20×14 格（320×224）。绘制顺序（自底向上）：

1. **地板**：客厅木地板（`tiles.png` 48×32 木地板块中段的可平铺格 `(32,16)` / `(32,32)` 随机混铺）；厨房区（右上 6×6 格）铺浅色瓷砖（`tiles.png` 右侧 1×2 瓷砖列的 `(496,96)`），交界处脚本用图集配色补 2px 门槛条（素材本身没有过渡格）。
2. **北墙**（2 格高 = 32px）：上 16px = 墙顶，下 16px = 墙面 + 4px 踢脚。由墙体列 A（米色，`tiles.png` @ `(240,16)`，48×32/块）拆成 16×32 竖条拼装：左端条自带 1px 暗边当左转角，右侧厨房段换墙体列 C（`tiles.png` @ `(368,16)`，上表面米色 + 下表面深蓝瓷砖 = 厨房挡水墙），右端条收边。
3. **东/西/南墙**（1 格厚）：俯视视角只能看到墙顶，素材没有侧墙模块，脚本用墙体上表面主色（采样 `(256,18)`）= `(228,200,176)` 拼 1 格厚墙条 + 内外沿暗线。**这是程序化补的，不是素材。**
4. **墙脚接触阴影**：北墙脚 / 三侧墙内沿，4 层渐隐暗色，脚本补。素材没有任何阴影层。
5. **墙面贴饰**（画在墙上）：挂画 ×2（16×11 / 28×11）、窗户 ×2（22×14 / 20×16）、红色双开门（30×19）、挂钟（18×18）。
6. **地毯等平面装饰**：青绿菱格地毯（客厅，34×32）、红色菱格地毯（餐区，34×32）。
7. **家具按 y 排序**（脚底线排序，实现前后遮挡）：书架、沙发、茶几、壁炉、紫色小沙发、餐桌 + 2 把高背餐椅、落地灯 ×2、落地钟、厨房台面 ×3、窄高储物架、矮书架、盆栽 ×5。
8. **角色按脚底 y 插入同一排序**：Alice 站在空地（全身 + 脚底 + 影子可见）；Bob 站在餐桌后——餐桌底边 y 大于 Bob 脚底 y，所以桌子盖住他的腿，**明确演示前后遮挡**。
9. **暖光/冷光斑**：壁炉橙色暖光 + 窗下冷光，脚本径向渐变补。素材没有灯光层。

### 1.2 角色锚点

- `alice.png` / `bob.png`：8×8 帧、每帧 48×48，帧内不透明像素范围 x=14..33、y=8..40，**脚底在帧内 y=40**，帧底还有 7px 空白。
- 当前 `animation-manifest.json` 的 `anchor = { x: 0.5, y: 1 }` 会让「帧底」对齐格底，等价于**角色脚底比格子底边高 7px（≈0.44 格）**。mock 里按真实脚底像素对齐地面，因此 mock 不会出现浮空；正式渲染器需要把锚点换算成 `y = 40/48`（或裁掉底部 7px 空白）才不浮空。
- 角色只有站/走/交互 3 组动画（每方向 4 帧），没有坐、躺、使用家具的姿势。

## 2. 复现说明

审计期间用 Python（Pillow + numpy）生成 mock；生成脚本属于本地审计工具，**未随仓库提交**（`workspace/` 已 gitignore），仓库中保留产出图与逐帧参数说明。复现时按 §1.1 的图层顺序与 §3 的图集帧坐标重放即可。

脚本约定：

- 素材全部按「图集文件名 + 像素盒子 (x, y, w, h)」从原图裁切，**不缩放、不重绘、不生成任何像素**；画出画布后再统一 4× nearest 放大。
- 只有墙体/地板的分层拼装、墙脚阴影、壁炉/窗光斑、门槛条是脚本用图集配色程序化补的，已在标注图里用蓝色框区分（黄色框 = 图集帧）。
- 输出图片为 RGB（无透明通道、画布干净），4× nearest 后尺寸严格 1280×896。

## 5. 结论：现有素材能否达到「像样像素风」—— **勉强**

**能的部分（本 mock 已证明）**

- 用墙体列拆条，能拼出 2 格高、带墙顶/墙面/踢脚和 1px 转角的直墙；配 2 格高门洞 + 红门，房间边界立得住。
- 木地板与瓷砖都能无缝平铺，能做出两种材质的分区，视觉上「像一间房」。
- 家具清单足够摆出客厅（沙发/茶几/书架/壁炉/落地钟/植物/灯）+ 餐区 + 厨房一角（台面/水槽/灶台/储物架），2 个角色 + y 排序 + 接触阴影后，整体观感接近独立小游戏 demo 的水平。
- 4× nearest 下像素块干净，风格统一（同一套配色：木色 + 米色墙 + 红蓝点缀）。

**勉强的部分（素材硬伤，不是调参数能补）**

1. **没有真正的墙体系统**：墙块只有「3 格宽 × 2 格高」的直墙整块，没有内/外转角、丁字/十字接合、东/西/南向墙、墙端盖、门洞过梁、踢脚线单条。任意拐弯只能硬切色块（本 mock 的东西南墙就是脚本画的）。
2. **没有门窗状态**：全库只有 2 张关闭的红门（30×19 / 28×23），没有门框/门套、门槛、开/关/锁帧；窗只有 4 种贴墙小窗，没有窗台/窗帘/窗外景，也不能真的「开窗」。
3. **没有灯光与阴影**：全库零阴影、零光斑、零发光件。本 mock 的墙脚阴影、壁炉暖光、窗口冷光全部是脚本程序化补的——意味着渲染器必须自己做，否则画面会像「贴纸平铺」。
4. **地毯是 34×32 固定单帧**：不能按 16px 网格伸缩、不能拼多格、不能压边，房间一大就露怯。
5. **家具透视与朝向不统一**：同一张表里混着俯视（椅子、地毯）和正视（书架、壁炉、橱柜、餐桌）；沙发只有南北两向、小椅子 4 向、没有开合/使用状态（抽屉、冰箱门、椅背拉出）。
6. **生活模拟刚需件缺失**：冰箱没有（manifest 的 refrigerator 帧实为浴缸）、无烤箱/微波炉/抽油烟机/上柜/吧台、无淋浴/花洒/洗手台；厨房只能摆一排台面。
7. **角色与家具没有互动姿势**：只有站/走/交互挥手，没有坐沙发、躺床、开冰箱等姿势，交互只能靠「站在旁边 + 高亮」表达。

**综合判定**：现有素材勉强能撑起**一张演示房 / 一个 starter room**（本 mock 即上限附近），但撑不起「多房间公寓 + 家具交互 + 昼夜灯光」的正式表现。建议：保留现有素材作 fallback，同时换/补素材库（见 §7）。

## 6. 素材缺口清单

### A. 现有素材可替代（能凑合，但要手工 + 额外渲染逻辑）

| 缺口 | 现有替代方案 | 代价 |
| --- | --- | --- |
| 内/外转角、丁字墙 | 墙体列左右端条自带 1px 暗边，可当「转角收边」 | 只能画直墙；拐角处靠硬切，两面墙不能自然接合 |
| 东/西/南向墙 | 取墙体上表面同色拼 1 格厚墙条（本 mock 做法） | 完全没有墙面细节，只能靠阴影制造厚度感 |
| 门洞/窗洞 | 门/窗是「贴在墙面上的 sprite」，不是真开洞 | 洞后无空间，门不能真的打开；门宽 30 与 2 格整宽 32 差 2px |
| 地板材质过渡 | 两种可平铺地板 + 脚本 2px 门槛条 | 没有过渡格，换材质只能硬切 |
| 地毯 | 9 张 34×32 单帧（带硬边框） | 不能伸缩/拼接；与 16px 网格不对齐；anchor 居中会错位 |
| 床/沙发/桌子朝向 | 只取现有帧，必要时用「朝南/朝北」两版 | 没有东西向沙发，没有 L 形组合 |
| 厨房设备 | 台面/水槽/灶台三件套 + 储物架 | 没有冰箱/烤箱/上柜，只能排成一字型台面 |
| 卫浴 | 浴缸、双马桶、镜子、毛巾架有；淋浴缺 | 卫浴能摆，但不完整 |
| 灯光/阴影 | 渲染器程序化补（本 mock 的接触阴影/光斑） | 素材零支持，全靠渲染器 |
| 多格家具/组合 | 只有单帧；书架/壁炉等大件是整块 | 无法组合、无法换色 |

### B. 彻底缺失（现有素材没有任何替代）

| 缺口 | 影响 |
| --- | --- |
| 墙顶/墙面/踢脚可拼接系统（四向 + 转角 + 端盖 + 门洞过梁） | 房间拐弯、多房间布局全部做不出来 |
| 门开/关/半开/锁状态帧、门框门套 | 开门交互无法有视觉反馈 |
| 窗帘/窗台/窗外景、窗洞 | 窗户只能当贴纸，没有「向外看」的层次 |
| 冰箱、烤箱、微波炉、抽油烟机、上柜、吧台、洗碗机 | 厨房只有台面，生活模拟的核心交互物缺失 |
| 淋浴间/花洒/洗手台/浴室地垫 | 卫浴场景不完整 |
| 灯光层：灯具发光、环境光、夜晚模式 | 昼夜/氛围完全缺失 |
| 多格地毯、可拼接地毯、地板过渡条、踢脚线单独条 | 地面层次单调，大房间显空 |
| 天花板/吊灯/顶灯 | 房间只能俯视，没有室内高度感 |
| 家具开合/使用状态帧（抽屉、柜门、椅子拉出） | 交互表现力弱 |
| 角色坐/躺/使用家具姿势 | 角色与家具无法「合体」演出 |
| 楼梯/多层/电梯/门牌等公寓元素 | 无法做多层公寓 |
| UI/交互素材（选择框、悬停边、路径脚印、交互图标） | 需要渲染器自己画（如当前 selection 缺失） |

## 7. 若换素材库，最该补的 Top 5 素材类型

1. **完整墙体系统**：四向墙 + 内外转角 + 丁字/十字 + 门洞过梁 + 墙顶/墙面/踢脚分层 + 端盖。决定「房间感」的第一要素。
2. **门窗系统**：门框/门套、开/关/锁状态、窗帘/窗台/窗外景、可通过的窗洞。
3. **厨房/卫浴设备组**：冰箱、烤箱、微波炉、抽油烟机、上柜、吧台、洗碗机、淋浴间、洗手台。生活模拟的核心交互对象。
4. **可拼接地面系统**：16px 网格多格地毯、地板过渡条、踢脚线、不同材质边缘。
5. **灯光阴影层 + 家具/角色状态帧**：灯具发光、AO/接触阴影、夜晚环境光；家具开合/使用帧、角色坐/躺姿势。

  - 门是 32×40 的错帧（内容仅 30×19，底部 21px 透明），被底锚点拉高；「冰箱」帧实为浴缸；「马桶」帧实为两个马桶并排；
  - 无 y 排序（所有对象同一 renderLayer=20，仅按 y/x 粗排）、无接触阴影、无光、无墙厚。
- **右（重编排）**：同样三张图集 + 角色帧，修正帧映射、拆墙列拼 2 格高墙、地板分区、y 排序遮挡、程序化阴影/光斑后的效果。差距全部来自「素材用法 + 渲染分层」，而不是换了素材；这也说明：**当前观感差的主因是映射错误 + 渲染结构缺失，但即使全修好，素材仍有 §6 的硬缺口。**

## 9. 已知局限（本 mock 没做的）

- 未做多房间/门开合/昼夜光；未做家具交互状态；未做角色坐姿（素材没有）。
